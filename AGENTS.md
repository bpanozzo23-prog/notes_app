# notes_app — instructions for agents

These apply to any agent working in this repository (Claude Code, Codex). `CLAUDE.md` imports
this file; rules live here once.

A personal notes app (PWA) for one owner, one phone, and (from Phase 4) one small sync service on
the owner's XPS. Simplicity and durability beat
features; the owner's notes are the one thing that must never be lost or leaked.

## Read order

1. `README.md` → Status: which phase is in progress.
2. `docs/BRIEF.md`: the contract. Read the sections a change touches; read all of it before
   planning a phase or changing storage, the editor, the data model, backup or the Claude policy.
3. `DECISIONS.md`: search it for the component or concept before re-litigating a choice.
4. The code the task touches. Look for existing components and utilities before adding a
   duplicate.

## Working agreement

- **Propose before building** anything larger than a fix: a short plain-language plan, then wait
  for approval. In Claude Code, use Plan Mode for this.
- **Record decisions as they are made**, in `DECISIONS.md`, with absolute dates and the reason.
- **Verify on the phone.** The dev server runs on the XPS with `--host`; report the Tailscale URL
  (`http://brent-dell-system-xps-l502x:5174/`) and ask the owner to check. The agent has no screen:
  say plainly what it did not see.
- **The owner's real notes on the XPS (Phase 4).** `~/notes` and `~/.local/share/notes_app-sync/`
  hold the owner's real notes once sync is connected. Agents working on the app never open them
  unless the owner asks in that session; check the service with `notes-sync status` (counts and
  dates only). Codex never opens them, for now. Tests and checks use temporary folders and the
  sample notebook. The live service changes only through `npm run sync-deploy`.
- **Never commit a note, a backup or a key.** `.gitignore` covers the known paths; keep it that way
  and check `git status` before every commit. Commit only when asked.
- **Real Claude requests cost the owner money.** Tests and shots use made-up fixtures. For real-API
  checks there is a test key at `~/.config/notes_app/test-key` (mode 600, outside the repo; its own
  Anthropic workspace `notes_app-tests` with a spend limit). Use it only against the made-up sample
  notebook, never the owner's notes; never print, log or copy it; never give it to Codex. Standing
  allowance (owner, 2026-10-18): up to **$1 per step** without asking, each run's cost reported;
  above that, ask first with the reason. Free calls (token counting) need no allowance.
  `npm run claude-check -- --real` drives the app with real requests on the sample notebook
  (question, follow-up, tidy, Apply, Undo; about 10¢) and writes `private-data/claude-check/`.
- **Explain choices and define jargon the first time it appears.** The owner reads everything.
- **Copy mi-cuaderno's patterns, not its code.** `~/code/mi-cuaderno` has the Dexie layer, backup
  export/import, the on-device Anthropic key with a spend cap, and the PWA/GitHub Pages setup.
  Read them when building the equivalent here.

## Environment

- The XPS (`uname` says `Linux`) is where the CLIs run, in bash inside `tmux` over SSH. There is
  no browser pane. The owner's machines and how they connect are documented in `~/code/devices`,
  not here.
- `npm run dev` serves on port 5174 with `--host` (mi-cuaderno uses 5173). Node 24, npm 11.
  It runs in the detached tmux session `notes-dev` inside a restart loop (log `/tmp/notes-dev.log`):
  Vite has died on an unhandled `ECONNRESET` when the phone dropped a connection.
- **Seeing the app:** `npm run shots [out-dir] [url]` renders the app in headless Chromium
  (Playwright, browser in `~/.cache/ms-playwright`, no sudo needed) at Pixel-7 size, walks the
  main screens and writes PNGs (default `private-data/shots/`, gitignored; default URL the dev
  server). Storage starts empty each run; the script imports `public/sample-notebook.json` (a
  made-up notebook generated by `scripts/make-sample-notebook.mjs`, also downloadable from the
  published app) through the real Settings → Import flow. Read the PNGs to check layout. Extend
  `scripts/screenshot.mjs` when a step adds screens, and the generator when a step adds content
  types; `src/db/sampleNotebook.test.js` keeps the file valid. It cannot show Samsung Keyboard/Gboard behaviour; the owner's phone
  remains the final check for typing.
- Multi-line commit messages: a bash heredoc (`git commit -F - <<'MSG' … MSG`); read the message
  back with `git log -1 --pretty=%B`.
- **The sync service (Phase 4)** runs on the XPS as the user unit `notes-sync` (`systemctl --user
  status notes-sync`, logs with `journalctl --user -u notes-sync`), listening on
  `127.0.0.1:8790` behind Tailscale Serve `:8443`. `notes-sync status` shows counts and dates
  only; `notes-sync pair` opens a 10-minute pairing window. Change it only with
  `npm run sync-deploy` (after committing; `--rollback` to go back); test with
  `npm run sync-check`, which uses temporary data. Note sessions start with `claude-notes`.
- **Never run `npx skills remove`** (it switched a checkout's branch mid-command once in
  mi-cuaderno).

## Tool notes

- **Claude Code:** `/rc` hands the running session to the Claude mobile app, which is how the
  owner steers it from the phone.
- **Codex:** the owner's real browser data is not available in Codex's test browser; verify
  against seeded fixture data and never treat an empty notebook as the owner's actual state.
  Subagents: at most two, read-only, for substantial reviews or independent investigations.
